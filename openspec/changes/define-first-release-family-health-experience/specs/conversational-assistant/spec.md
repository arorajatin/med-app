## Purpose

Define retained, provider-neutral conversations for one selected family profile using reviewed personal memory and clearly attributed external information.

## ADDED Requirements

### Requirement: Scope each conversation to one family profile
The account manager SHALL select an owned family profile before starting Chat, and each conversation SHALL remain scoped to exactly that profile.

#### Scenario: Start a conversation
- **WHEN** the account manager selects an owned profile and starts Chat
- **THEN** the system SHALL create a conversation owned by the account and scoped to that profile

#### Scenario: Ask about another family member
- **WHEN** a message in one profile's conversation requests private context from another profile
- **THEN** the assistant SHALL NOT retrieve or disclose the other profile's private information
- **AND** the user SHALL be directed to start or open a conversation under the intended profile

#### Scenario: Select a foreign profile
- **WHEN** a user attempts to start Chat for a missing or unowned profile
- **THEN** the service SHALL respond as though that profile was not found

### Requirement: Ground personal answers only in trusted memory
The assistant SHALL use only reviewed or user-attested medical-memory facts for personal claims about the selected profile and SHALL exclude pending candidate memory and unreviewed metric observations.

#### Scenario: Reviewed personal evidence is available
- **WHEN** a question is supported by trusted memory for the selected profile
- **THEN** the answer SHALL distinguish the personal claim from general information
- **AND** it SHALL retain a citation to the supporting memory fact and source report when one exists

#### Scenario: Personal evidence is unavailable
- **WHEN** the selected profile has no trusted memory supporting a requested personal claim
- **THEN** the assistant SHALL state that the personal records do not provide that evidence
- **AND** it SHALL NOT invent a personal medical fact

#### Scenario: Evidence is awaiting review
- **WHEN** relevant extracted candidates remain pending or ignored
- **THEN** the assistant SHALL NOT use them as trusted personal evidence

### Requirement: Attribute external information
The assistant MAY supplement an answer with current external information, but SHALL distinguish it from personal memory and SHALL retain the actual external source links used.

#### Scenario: Use external information
- **WHEN** the assistant uses external information in an answer
- **THEN** the response SHALL identify it as external information
- **AND** it SHALL provide links to the actual supporting sites when available

#### Scenario: External retrieval is unavailable
- **WHEN** external retrieval fails or yields no support
- **THEN** the assistant SHALL state the limitation
- **AND** it SHALL NOT fabricate source links

#### Scenario: Prepare an external query
- **WHEN** the system queries an external information source
- **THEN** it SHALL minimize or remove direct personal identifiers and unrelated private medical context

### Requirement: Retain conversation history privately
The system SHALL retain conversation and message history under the owning account and selected profile, including completion state and the personal and external citations used for each answer.

#### Scenario: Reopen a conversation
- **WHEN** the account manager reopens an owned conversation
- **THEN** the system SHALL return its messages in conversation order
- **AND** the original profile scope SHALL remain unchanged

#### Scenario: Answer generation fails
- **WHEN** the selected model or retrieval path fails before an answer completes
- **THEN** the message SHALL expose a safe failed or retryable state
- **AND** partial output SHALL NOT be represented as a completed answer

#### Scenario: Read another account's history
- **WHEN** a user requests a conversation owned by another account
- **THEN** the service SHALL respond as though that conversation was not found

### Requirement: Keep the assistant provider-neutral
The observable Chat contract SHALL support changing the configured model and external-retrieval providers without changing conversation ownership, grounding, citation, or history behavior.

#### Scenario: Use a supported configured provider
- **WHEN** a conversation response is generated by any supported configured provider
- **THEN** the system SHALL apply the same profile isolation, trusted-memory, attribution, and history requirements

#### Scenario: Provider configuration is unavailable
- **WHEN** no supported provider is configured for an enabled Chat environment
- **THEN** Chat SHALL fail closed without sending private context to an unintended fallback
